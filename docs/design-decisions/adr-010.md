# ADR-010: 采用能力驱动的异构资源模型

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、9 章；development-plan.md 1.2、5.1、WP-5.1

## 背景

不同厂商的 GPU 与异构加速器在驱动、内存、拓扑、分片（如 MIG）与调度约束上差异很大。如果强行用一个统一模型描述所有硬件行为，要么丢失关键能力（导致调度错误或性能损失），要么不断在核心中加入厂商特例（破坏微内核与插件分离）。

## 决策

**采用能力驱动的异构资源模型**：

- 通过 **DeviceProfile** 等结构**显式表达能力**（内存、算力、分片能力、拓扑等），资源需求与设备能力以能力匹配方式对接。
- **厂商差异通过 Provider 显式表达**，不强行统一底层硬件行为；厂商特有语义由对应 Provider 承载。
- 核心资源模型保持厂商中立，只描述通用、可声明的能力维度。
- 优先从 NVIDIA Provider 起步，后续通过相同机制扩展其他厂商（ADR-001/ADR-006）。

## 后果

**正面**

- 可平滑扩展新厂商与新设备类型，无需改动核心行为。
- 能力匹配让调度更准确，减少资源错配。
- 与微内核/插件分离一致，厂商细节收敛在 Provider 内。

**代价与约束**

- 能力模型与匹配算法本身较复杂，需要清晰的 Schema 与校验。
- 不同 Provider 对能力的表达需保持一致语义，依赖契约测试保证互操作性。
- 能力不足或描述错误会直接影响调度结果，需要可观测与可追溯。
