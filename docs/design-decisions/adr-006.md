# ADR-006: 插件按信任级别隔离

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、8、14 章；development-plan.md 1.2、5.7、WP-0.3、WP-4.6

## 背景

ForgeMesh 允许第三方与厂商插件扩展能力。但并非所有插件都可信：厂商官方插件、社区插件与未知来源插件带来的风险不同。如果所有插件都在核心进程内以完全权限运行，一个恶意或有缺陷的插件就可能危及核心状态、越权访问其他租户数据，甚至执行任意操作。

## 决策

**插件按信任级别隔离执行**：

- 定义两种宿主模式：
  - **进程内（in-process）**：适用于受信任、低风险的插件。
  - **受限 RPC（restricted RPC）**：适用于第三方或高风险插件，运行在隔离进程/沙箱中，通过受控协议通信。
- 插件必须通过 **Plugin Manifest** 声明其能力与所需权限；核心在加载前进行校验，遵循**最小权限**原则。
- 高风险或第三方插件**默认采用隔离执行**；核心不因插件请求而授予超出其声明的权限。
- 插件不能直接写入其他插件的私有数据，也不能绕过核心改变权威状态（不变量一）。

## 后果

**正面**

- 降低第三方插件的安全风险，保护核心与跨租户数据。
- 信任级别可调，兼顾信任插件的性能与未知插件的隔离。
- 权限声明为审计与治理提供依据。

**代价与约束**

- 隔离执行的插件引入 RPC 通信开销与序列化约束，性能低于进程内调用。
- 需维护两种宿主模式的一致契约、权限模型与生命周期管理。
- 需配套安全测试（越权、租户隔离、插件权限与密钥泄露）。

参见 [`SECURITY.md`](../../SECURITY.md) 关于插件签名与制品校验的要求。
