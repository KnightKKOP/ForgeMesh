# ADR-013: 权威存储采用 SQLite 先行、PostgreSQL 为目标态的过渡策略

- 状态: Accepted
- 日期: 2026-10-11
- 决策者: ForgeMesh 架构组
- 相关: ADR-007；architecture.md 第 2、7 章；development-plan.md 1.2、WP-1.2

## 背景

ADR-007 确定 PostgreSQL 为权威业务存储（目标态）。但实施到当前阶段（v1.0.x）发现：

- 部署形态为**单控制平面实例**，无多实例并发写需求，数据库级并发仲裁能力暂无用武之地；
- 引入 PostgreSQL 需要迁移工具链（Alembic）、独立部署依赖与运维成本，与当前"轻量起步、快速验收"的交付节奏不匹配（docker-compose 中控制平面未连接数据库）；
- v1.0.0 变更日志曾声称已交付"PostgreSQL 权威存储"，与实现脱节，需要以正式决策收编该过渡状态，避免文档继续虚报。

实现现状：`control-plane` 包的 `SQLiteRegistry`（`registry/store.py`）对齐 `core-contracts` 的 `ResourceRegistry` 契约，以 SQLite 作为权威状态后端；并发控制采用应用层 CAS 乐观并发（`resource_version`），租户隔离以 `tenant_id` 作为首要过滤条件。

## 决策

**实施过渡期以 SQLite 为权威存储后端，PostgreSQL 仍为权威存储目标态**：

- Repository 契约（`ResourceRegistry` 抽象）保持与后端无关：SQLite 与未来的 PostgreSQL 提供等价实现，上层（Controller、调和循环、REST API）不得感知具体后端。
- SQL 方言限定为 SQLite 与 PostgreSQL 的**兼容子集**：DDL/DML 必须能在两者上等价执行。
- 禁止 PostgreSQL 独有特性（`LISTEN/NOTIFY`、advisory lock、行级安全 RLS）进入核心路径；确需这些能力时仅允许存在于 PostgreSQL 专属适配层，且 SQLite 路径必须具备等效降级实现。

## 迁移判据

满足以下条件**之一**即启动 PostgreSQL 迁移（届时引入 Alembic 版本化迁移脚本）：

1. 控制平面需要**多实例部署**（高可用/水平扩展），出现数据库级并发仲裁需求；
2. 管理规模超过 **200 节点 / 2000 GPU**，SQLite 单文件写入吞吐或容量成为瓶颈；
3. 需要**租户级行级安全（RLS）**等数据库层隔离能力。

## 后果

**正面**

- 单机部署形态下数据与控制平面共存，零外部数据库依赖，起步与备份成本最低（备份策略见 [docs/operations/backup-restore.md](../operations/backup-restore.md)）。
- `ResourceRegistry` 抽象锁定 Repository 契约，后端切换不影响上层代码。
- CAS 乐观并发（`resource_version`）语义与 ADR-007 要求的资源版本机制一致，迁移后语义可平移。

**代价与约束**

- 多实例并发写依赖应用层 CAS，**无数据库级仲裁**；在迁移判据满足前，不得部署多个控制平面实例并发写权威存储。
- SQLite 下 ADR-007 所要求的"数据库事务、唯一约束或等效机制"由应用层 CAS + `PRIMARY KEY(tenant_id, kind, namespace, name)` 唯一约束近似满足，缺少领导者选举与跨进程仲裁。
- 单机形态下数据随控制平面共存亡，备份/恢复必须连同控制平面一并纳入运维流程。

**与 ADR-007 的关系**

ADR-007 描述权威存储的目标态（PostgreSQL），本 ADR 记录实施过渡策略，**不推翻 ADR-007**。迁移判据满足时，按本 ADR 启动 PostgreSQL 迁移，届时以新 ADR 记录迁移决策并结束本过渡期。
