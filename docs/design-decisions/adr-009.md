# ADR-009: Node Agent 采用受认证的任务协议

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、10、14 章；development-plan.md 1.2、5.9、WP-3.2

## 背景

Node Agent 运行在计算节点上，负责执行实际的资源操作（准备环境、启动/停止推理服务、采集状态等）。如果控制平面可以通过任意远程 Shell 命令驱动 Agent，则缺乏授权粒度、审计能力与幂等保障，任何凭证泄漏或越权都可能演变为节点上的任意代码执行，安全风险极高。

## 决策

**Node Agent 采用受认证的任务协议**：

- 控制平面与 Agent 之间使用**版本化的受认证任务协议**（gRPC / Protobuf 或等价版本化 RPC）。
- Agent **仅接受有类型的任务**（如 PrepareEnvironment、DeployInferenceService、HealthCheck 等受控操作），**禁止默认执行任意远程 Shell**（不存在通用的 `RunShell` 任务类型）。
- 任务须携带稳定标识，执行保证**幂等**；支持**断线恢复**与任务重放的安全处理。
- 连接须双向认证，任务须经授权与审计。

## 后果

**正面**

- 消除"任意远程 Shell"这一高风险面，操作可授权、可审计、可追溯。
- 有类型任务便于幂等设计、恢复与版本管理。
- 节点失联后，资源状态不会未经验证就被标记为可用。

**代价与约束**

- 需定义任务类型集合与协议版本，并维护向后兼容（见 ADR-012）。
- 复杂运维动作若无法表达为有类型任务，需通过新增任务类型而非开放通用 Shell。
- 需实现双向认证、任务幂等与断线恢复，工程复杂度上升。
