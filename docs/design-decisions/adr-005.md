# ADR-005: Scheduler 与 Policy 拥有最终治理权

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、7、11 章；development-plan.md 1.2、5.6、WP-1.4、不变量三测试

## 背景

当决策系统（尤其是 LLM/JEV）给出"选择某块 GPU、部署某服务"的建议时，容易被误当作已经获得执行许可，从而绕过授权、配额与资源可行性检查。这会破坏多租户隔离、配额治理与资源安全——一个"推荐"不应等价于一次"授权"和一次"分配"。

## 决策

**Scheduler 与 Policy 拥有最终治理权**：

- 任何资源分配或操作授权，**必须**依次经过：
  - **Policy Engine**：授权、准入、配额规则与审批要求；
  - **Resource Scheduler**：资源可行性、分配、冲突检测与释放。
- 决策系统（JEV/LLM/规则）可以**选择或推荐候选方案**，但**不能跳过** Policy 与 Scheduler 检查，更不能直接写入资源最终状态。
- 架构不变量三：**决策不等于授权**。工作流不能绕过 Scheduler 直接分配 GPU。

## 后果

**正面**

- 治理与决策解耦，安全边界清晰，符合多租户与配额治理目标。
- 决策可自由更换（规则/JEV/LLM），不影响治理正确性。
- 提供明确的不变量测试点：未授权操作不会因决策推荐而执行。

**代价与约束**

- 完整链路更长（决策 → Policy → Scheduler → WorkEngine），需妥善处理各阶段失败与重试。
- 必须实现并覆盖"决策≠授权"的架构不变量测试。
- Policy 与 Scheduler 自身需具备高可用与一致性保障，否则会成为瓶颈或单点。
