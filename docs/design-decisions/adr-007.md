# ADR-007: PostgreSQL 作为权威业务存储

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、12 章；development-plan.md 1.2、WP-1.2

## 背景

平台需要决定"哪一种存储才是权威状态（Source of Truth）"。若让缓存或事件系统承担权威状态，容易因缓存失效、事件丢失或顺序问题导致数据不一致、状态失真；而多租户、配额、并发分配等语义又要求强一致与事务能力。

## 决策

**PostgreSQL 是权威业务存储**：

- 所有资源的权威状态（含版本、状态、租户边界）持久化于 PostgreSQL。
- 缓存系统（如 Redis）**仅用于缓存与限流**，不得作为权威状态来源。
- 事件系统（Event Bus）用于异步通知与解耦，**不能取代**权威状态；外部事件只能触发协调，不能被无条件视为真实状态。
- 并发控制依赖数据库事务、资源版本、唯一约束、租约或等效机制（见 ADR-008），而非单进程内存锁。

## 后果

**正面**

- 权威状态强一致、可事务化，为多租户隔离、配额与并发分配提供可靠基础。
- 缓存与事件系统可独立替换或降级，不影响正确性。
- 支持控制器多实例部署与崩溃后恢复。

**代价与约束**

- 引入对 PostgreSQL 的运行时依赖，需要迁移与版本管理（开发计划第 7 章）。
- 缓存需明确失效策略，避免脏读引发的误判。
- 需处理控制器多实例下的并发协调与领导者选举（选举不能替代数据层并发保护）。
