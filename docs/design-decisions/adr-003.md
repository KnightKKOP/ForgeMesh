# ADR-003: WorkEngine 采用可替换 Provider

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、6 章；development-plan.md 1.2、5.4、WP-2.1 / WP-2.2

## 背景

ForgeMesh 需要可靠地执行长流程（部署推理服务、健康验收、资源回收等），要求持久化、幂等、重试、补偿、取消与恢复。项目面临一个选择：从一开始自研一个完整的通用工作流引擎，还是直接绑定某个成熟引擎（如 Temporal）。前者成本高、易偏离核心价值；后者会让业务模型被引擎内部类型绑架，难以更换或自建。

## 决策

ForgeMesh **定义自己的工作流运行契约（WorkEngine）**，但**不要求从第一天起自研完整通用引擎**：

- 在核心接口中定义工作流的运行语义：状态、步骤、持久化、幂等、重试、补偿、取消、恢复、执行历史与版本固定。
- 建立**参考执行 Provider** 验证契约完整性；先通过故障测试评估自有执行器与成熟引擎的适用性。
- 必要时通过 **Temporal 等 Provider** 复用成熟执行能力。
- **业务资源模型不得依赖任何工作流引擎的内部类型**；执行后端可替换，但替换后端不得改变业务工作流的基本语义。

## 后果

**正面**

- 业务模型与执行引擎解耦，符合"可移植：工作流引擎可替换"目标。
- 先冻结契约再选型，避免过早绑定；可用参考执行器持续验证契约。
- 引擎级故障恢复能力可来自成熟 Provider，降低自研风险。

**代价与约束**

- 需自行维护工作流契约与至少一个参考执行器，并配套契约测试。
- 契约设计必须覆盖幂等、补偿、恢复与版本固定等边界语义。
- 更换执行 Provider 时须回归验证，确保语义不发生静默变化（见 ADR-011）。
