# ADR-012: 所有公共契约版本化

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、13、17 章；development-plan.md 1.2、WP-0.5、第 8 章

## 背景

ForgeMesh 通过公共契约（REST API、资源 Schema、领域事件、插件协议、Agent 协议）与外部及第三方交互。若公共契约没有版本管理，任何字段增删、语义调整都会"静默破坏"下游，插件生态与第三方工具将无法稳定跟进，升级成本不可控。

## 决策

**所有公共契约版本化**：

- 所有 API、Schema、事件与插件协议**带版本前缀**（如 `forgemesh.io/v1alpha1`），并进行版本兼容性管理。
- 通过 **Schema、兼容性测试与弃用周期**管理演进：
  - 向后兼容变更走 minor 版本，并更新 Schema 与契约测试；
  - 破坏性变更须经 **ADR**、采用新版本前缀，并提供迁移与弃用计划。
- 社区提供**插件开发模板与契约测试套件**；公共接口变更执行兼容性评审（见 [`GOVERNANCE.md`](../../GOVERNANCE.md) 第 4 节）。
- 架构文档与开发指南纳入持续集成检查。

## 后果

**正面**

- 兼容性可控、升级可预期，保护插件生态与第三方集成。
- 版本前缀让新旧契约可并存，支持渐进迁移。

**代价与约束**

- 需要维护契约测试套件、版本矩阵与弃用流程，工程与文档负担增加。
- 破坏性变更的评审与迁移成本更高（这是有意为之，以换取生态稳定）。
- 所有公共契约变更必须附契约测试，禁止静默破坏。
