# ADR-004: JEV 不是唯一决策系统

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、7 章；development-plan.md 1.2、5.5、WP-2.3 / WP-2.4

## 背景

不要把平台的所有决策都寄托在单一系统上。有的场景适合确定性规则（如资源约束匹配），有的适合类型化决策模型（JEV），有的才需要 LLM 辅助。若把 JEV（或 LLM）当作唯一决策后端，会导致：简单场景被过度复杂化、确定性场景失去可复现性、某个决策后端不可用时整条链路不可用。

## 决策

**JEV 不是唯一决策系统**。项目支持多种决策 Provider：

- 定义类型化决策契约 `DecisionProvider`，并以 **Decision Router** 统一选择、超时、熔断、降级与输出校验。
- **规则 Provider 为首个确定性实现**；JEV、LLM 及其他 Provider 作为可选后端并列存在。
- Router 负责在目标 Provider 超时/失败时**降级**到确定性规则或安全默认，并校验输出格式与合法性。
- 决策 Provider 的输出仅为**建议**，不构成授权（见 ADR-005）。

## 后果

**正面**

- 不同场景可选用最合适的决策方式，兼顾确定性与灵活性。
- 单个 Provider 故障可降级，提升可用性。
- 规则 Provider 保证核心路径可复现、可测试。

**代价与约束**

- 需维护多 Provider 的一致语义与统一输出契约。
- Router 需要实现选择、超时、熔断、降级与输出校验逻辑，复杂度上升。
- 决策输出必须经 Policy/Scheduler 校验，不得直接改变资源终态。
