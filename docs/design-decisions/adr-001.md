# ADR-001: 微内核与插件分离

- 状态: Accepted
- 日期: 2026-10-09
- 决策者: ForgeMesh 架构组
- 相关: architecture.md 第 2、4、8 章；development-plan.md 1.2、WP-0.2 / WP-1.5 / WP-4.6

## 背景

ForgeMesh 需要持续支持 NVIDIA、MIG、vLLM 以及未来更多异构设备与推理运行时。如果核心代码直接耦合具体厂商实现，每新增一种设备或运行时都要修改核心，与"可扩展：业务能力通过稳定接口扩展，不依赖修改核心代码"的目标相矛盾；同时也会让核心状态与治理逻辑被领域细节淹没，难以保证一致性与安全性。

## 决策

采用**微内核（Microkernel）+ 插件（Plugin）分离**的架构：

- **核心微内核**只定义稳定契约与治理能力：Resource Registry、Reconciliation Controller、Policy Engine、Resource Scheduler、Plugin Manager、Audit Manager。核心掌握权威状态与治理权。
- **插件**实现具体领域能力：GPU、Runtime、Model、MIG、Quantization、QoS、Metering 等，通过稳定契约接入。
- 插件**仅依赖 Plugin SDK**，禁止反向依赖核心内部实现；业务/领域模型不引入插件的私有类型。
- 核心与插件之间通过版本化的接口契约通信（见 ADR-012），核心可在加载前校验插件的能力声明与权限。

## 后果

**正面**

- 扩展新设备/运行时无需修改核心代码，第三方可独立开发插件。
- 核心契约稳定，便于长期演进与生态建设。
- 能力可插拔、可替换，符合"可移植"目标。

**代价与约束**

- 必须长期维护稳定契约与版本管理，并配套契约测试（`tests/contract`）。
- 插件不得绕过核心直接改变其他模块的权威状态（架构不变量一）。
- 核心与插件边界的划分需持续评审，避免契约泄漏内部实现。
