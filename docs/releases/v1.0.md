## 勘误与现状（2026-10-11）

> 本节为 v1.1 发布前置的事实统一勘误（WP-A1）。下文原文保留作历史记录，但其中 PostgreSQL 相关表述与 ADR-013 不一致，稳定性、认证等多处表述与实现不符，请以本节为准。

1. **不一致范围**：本文 P1 功能表中的「PostgreSQL 权威业务存储（ADR-007）」（原 L49）、已知限制第 4 条「权威存储仅支持 PostgreSQL；SQLite 仅用于测试」（原 L111）、升级指南前置条件「PostgreSQL ≥ 14（生产部署）」（原 L124）与升级步骤「备份 PostgreSQL 数据库」「数据库迁移：`forgemesh migrate upgrade`」（原 L129 起）等表述，均为 v1.0.0 发布时记录的目标态描述，与 [ADR-013](../design-decisions/adr-013.md) 的实际交付决策不一致。
2. **当前事实**：依据 ADR-013，v1.0.x 的权威存储为 **SQLite**（`SQLiteRegistry` 实现 `ResourceRegistry` 抽象，应用层 CAS 乐观并发 `resource_version`）；PostgreSQL 为权威存储**目标态**，迁移判据（多实例部署 / 规模超限 / 租户级 RLS 需求）见 ADR-013。
3. **重要警告**：本文档中的 PostgreSQL 备份与迁移命令（如 `forgemesh migrate upgrade`）在当前版本**不存在、不可用**，请勿执行。
4. **权威操作指引**：备份与恢复流程请以 [docs/operations/backup-restore.md](../operations/backup-restore.md)（SQLite 备份/恢复与单实例写入约束）为准。
5. **认证表述**（2026-10-12 补充）：已知限制第 5 条「内置 API Key 与 OIDC 认证」与 v1.0.x 实现不符——网关只检查 `X-Tenant-ID` 请求头是否存在，控制平面直接信任该请求头，两者都不校验凭证。绑定租户的 API Key 认证自 v1.1.0 起提供（[ADR-014](../design-decisions/adr-014.md)）；OIDC 与 mTLS 尚未实现。
6. **稳定性表述**（2026-10-12 补充）：文首与「发布概要」中的「首个稳定版本」「API 兼容性冻结」，以及「兼容性保证」一节，与 v1.0.x 的实际状态不符：可运行入口的业务端点仍返回 `501`，没有认证，v1.1.0 也包含多项破坏性变更。API 稳定性标注已更正为 `beta`（OpenAPI `info.x-stability`），beta 阶段的规则与改回 `stable` 的前提见[弃用政策](../governance/deprecation-policy.md) 1.4 节。
7. **其他能力表述**（2026-10-12 补充）：以下条目与 v1.0.x 实现不符——P3 的「gRPC 通信：控制平面 ↔ Node Agent 双向流」（`agent.proto` 没有生成代码，只有进程内调用）；P4 的「可观测性：Prometheus metrics + OpenTelemetry tracing」（指标与追踪只记录在内存中，没有导出）与插件安全沙箱（没有进程级隔离，签名为 HMAC 对称签名且注册时不验签）；P5 的「Temporal 插件：生产级工作流编排引擎集成」（只有内存实现）。逐条说明见 [CHANGELOG](../../CHANGELOG.md) 1.1.0 Fixed 中的勘误条目，各项能力的现状见 README「功能概览」。

## 发布概要

ForgeMesh v1.0.0 是项目首个稳定版本，标志着从 P0（工程骨架）到 P5（扩展与生态）六个阶段的完整交付。本版本实现了完整的控制平面、工作流引擎、执行平面、生产级治理和生态扩展能力，API 兼容性正式冻结。

- **测试覆盖**：898 个测试，56 个测试文件
- **代码规模**：176 文件，约 17,745 行（Python 16,666 行 + Go 1,079 行）
- **架构决策**：12 个 ADR 已采纳（ADR-001 ~ ADR-012）
- **插件生态**：9 个内置插件 + 1 个插件 SDK

## 已知限制

1. **单集群部署**：v1.0 仅支持单 Kubernetes 集群部署，多集群联邦调度计划在 v1.1。
2. **GPU 厂商**：当前仅内置 NVIDIA GPU Provider，AMD/Intel GPU 需通过插件 SDK 自行实现。
3. **工作流引擎**：内置参考执行器适用于开发与小规模生产；大规模生产建议使用 Temporal 插件。
4. **存储后端**：权威存储仅支持 PostgreSQL；SQLite 仅用于测试，不建议生产使用。
5. **认证**：内置 API Key 与 OIDC 认证；mTLS 双向认证计划在 v1.1。
6. **模型仓库**：v1.0 不内置模型仓库管理，需通过外部仓库（HuggingFace/OSS）配合运行时插件使用。
7. **自动扩缩容**：基于队列深度的 HPA 策略需手动配置；自动弹性策略计划在 v1.1。

## 升级指南（从 0.x 到 1.0）

### 前置条件

- Python ≥ 3.12.15
- Go ≥ 1.22
- PostgreSQL ≥ 14（生产部署）
- NVIDIA Driver ≥ 535（GPU 节点）

### 升级步骤

1. **备份**：备份 PostgreSQL 数据库和配置文件。

2. **更新依赖**：
   ```bash
   git fetch origin
   git checkout v1.0.0
   source .venv/bin/activate
   pip install -e .
   ```

3. **数据库迁移**：
   ```bash
   forgemesh migrate upgrade
   ```

4. **配置变更**：
   - API 版本前缀不变（`/api/v1/`），无需修改客户端 URL。
   - OpenAPI `info.version` 从 `0.0.1` 变更为 `1.0.0`，如有版本校验逻辑需更新。
   - 所有 501 Not Implemented 端点已正式实现，移除客户端中的 501 降级逻辑。

5. **插件更新**：
   - 插件接口未变更，现有插件无需修改。
   - 建议通过插件 SDK 重新生成契约测试：`forgemesh plugin sdk scaffold --recheck`。

6. **验证**：
   ```bash
   forgemesh healthz
   forgemesh readyz
   pytest
   ```

### 破坏性变更

v1.0 相对于 0.x 阶段性版本**无破坏性变更**。0.x 版本为开发阶段版本，不提供升级兼容保证；v1.0 是首个具有兼容性保证的版本。

## 兼容性保证

### API 稳定性

- **major 版本内保证向后兼容**：v1.x 系列中，所有已发布的 API 端点和字段保持向后兼容。
- **新增不破坏**：新增端点、字段、可选参数不影响现有客户端。
- **语义化版本**：
  - **major**（如 2.0.0）：允许破坏性变更，提前在 CHANGELOG 中公告。
  - **minor**（如 1.1.0）：新增功能，向后兼容。
  - **patch**（如 1.0.1）：Bug 修复，向后兼容。

### 契约保护

- OpenAPI 规范（`api/openapi/openapi.yaml`）作为 API 契约权威来源。
- JSON Schema（`api/schemas/`）作为资源模型权威契约。
- 兼容性测试套件（`tests/compat/`）在 CI 中持续守护契约不回归。

## 弃用政策

当 API 端点或字段需要弃用时：

1. **标记**：在 OpenAPI 中添加 `x-deprecated: true` 扩展字段。
2. **记录**：添加 `x-deprecated-since`（弃用版本）和 `x-deprecated-removal`（计划移除版本）。
3. **保留期**：弃用端点至少保留 **2 个 minor 版本**（如 v1.1 弃用，最早 v1.3 移除）。
4. **公告**：在 CHANGELOG.md 的 `Deprecated` 分类中记录。
5. **迁移**：在发布记录中提供迁移指南。

完整弃用政策见 [docs/governance/deprecation-policy.md](../governance/deprecation-policy.md)。
